# Find4Sport working agreement

Confirmed by the project owner on 2026-10-21.

- GitHub `main` is the source of truth for integrated code. Fetch `main`, work in a review branch and integrate reviewed changes through the repository's checks.
- Notion is the source of truth for requirements, architecture, decisions, planning, standards, QA and delivery evidence. Use the existing project template and existing records before creating new ones.
- Prioritize free-user acquisition, a useful first action and repeat use before monetization. Registrations, active users, recurring users and revenue are separate measures.
- Apply relevant security, privacy/RGPD, accessibility, usability, UI/UX, performance, component reuse and data-quality practices during implementation. An ISO/WCAG checklist or code change alone is not certification or evidence of full compliance.
- For each meaningful change, update the affected requirement, architecture/component or decision record, task and tests/results. Link the source requirement, task, commit/PR, environment, date and evidence. Preserve historical evidence and distinguish local, CI, Preview and production results.
- Coordinate specialist agents with explicit file ownership; review their changes together and validate after concurrent edits have stopped.
- Report progress against an explicit delivery scope and denominator. Do not invent a completion percentage for the entire platform from a small correction batch.
- Keep release gates active. Distinguish code integration from production readiness and production deployment; do not bypass quota, migration, security or authenticated-flow restrictions.
